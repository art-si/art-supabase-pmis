## 项目定位

亿企工场 PMIS 承载生产设备的日常运维。围绕已有设备、组织产线与员工身份，维护运维方案、执行任务、检查项目、结果记录和分析，帮助操作人员追踪待办、逾期、异常和维修处理。

本仓维护 PMIS 页面、领域 API、类型和设备任务规则。认证、租户、动态菜单、按钮权限、主题、布局、公共组件和 Supabase 公共运行时由 [`art-supabase-pro`](https://gitee.com/art-si/art-supabase-pro) 提供。设备点检和设备巡检保留各自的菜单及业务语义。

## 当前能力

| 领域       | 已有能力                                                                          |
| ---------- | --------------------------------------------------------------------------------- |
| 运维工作台 | 五类业务能力导航、任务闭环说明及租户/权限边界                                     |
| 设备点检   | 点检表、点检方案、明细、记录报表、分析和设备点检看板                              |
| 设备巡检   | 巡检方案、任务、明细、记录报表与分析                                              |
| 设备保养   | 部门设置、保养方案、任务、明细、记录报表与分析                                    |
| 故障维修   | 维修人员设置、维修任务、维修处理与维修分析                                        |
| 预防维修   | 预防维修方案、任务、明细与分析                                                    |
| 任务办理   | 新增、编辑、参考复制、执行、确认、详情及记录追踪，按对应业务权限开放              |
| 范围与分析 | 部门/产线树形筛选、日历查看、设备/责任人维度汇总、待办/完成/逾期/豁免状态与完成率 |

分析和日历基于实际任务读取。完成率计算排除豁免任务；详情通过记录身份重新读取，并保留设备、组织、人员和执行结果上下文。页面出现哪些操作，取决于当前角色的精确按钮权限及任务状态。

## 近期完善

- 方案、任务和维修工作区统一部门导航、筛选、详情、引用身份与查询错误反馈。
- 方案项目、任务编辑、现场执行、维修和部门设置使用平台配置式表单与公共选择器。
- 分析口径集中在领域模块，日历、分析及维修分析保持各自的查询范围；看板按真实任务呈现状态。
- 单条及批量删除复用 `MasterDataDeleteGuard`，确认前检查引用；失败或无权限时阻止删除，保留可重试反馈。
- 共享工作区复用平台加载、空态、错误重试、滚动区和主题，主仓与独立开发使用同一套业务实现。

## 推荐办理顺序

```text
核对设备、部门/产线与人员
  → 维护点检/巡检/保养/预防维修方案
  → 办理任务与现场执行
  → 记录检查结果、异常与维修处理
  → 确认结果并查看记录
  → 日历、看板及分析复核
```

计划、执行、确认和维修由对应业务页面办理。分析页显示汇总结果，不作为修改任务或设备状态的入口。尚未配置设备、人员或方案时，应先补齐权威资料，不按名称重复创建身份。

## 与 MES 和主平台协作

MES 生产执行可以关联设备与 PMIS 任务，生产报工和设备维护仍有各自的状态、权限与审计。核对故障或维护影响时使用真实记录关联，不只按设备名称推断。

通用工具、组件和运行时由主平台维护；跨域数据通过最小字段、租户隔离的 API/RPC 契约访问，本仓不直接复制或导入其他业务仓源码。业务修改先在本仓提交推送，再更新主仓 `modules/art-supabase-pmis` 子模块指针。

## 本地开发

环境要求：Node.js `>= 22.13.0`、pnpm `>= 11.28.2`。

```powershell
pnpm install
pnpm dev
```

默认地址为 `http://localhost:3020`。可在主仓的 `modules/art-supabase-pmis` 中开发，也可独立克隆并安装 `package.json` 中固定的平台依赖。通过 `ART_SUPABASE_PLATFORM_ROOT` 可指定本地平台目录。

共享 Vite 工厂合并平台和应用环境配置；部署前核对自己的后端与公共路径，浏览器变量不得包含服务端密钥。

| 命令                  | 用途                             |
| --------------------- | -------------------------------- |
| `pnpm boundary:audit` | 检查模块所有权和依赖边界         |
| `pnpm typecheck`      | 使用共享模块入口检查类型         |
| `pnpm check`          | 边界/UI 审计、类型检查与 ESLint  |
| `pnpm build`          | 类型检查并构建静态产物到 `docs/` |
| `pnpm preview`        | 预览构建结果                     |

公共路径由 `VITE_BASE_URL` 控制。菜单由服务端下发，完整菜单路径与本仓 `src/views/**/index.vue` 逐段一致；角色没有菜单授权时不会展示对应入口。

## 权限与数据安全

- 普通用户只访问已认证租户内的授权数据；租户管理员不能跨租户操作。
- 平台超级管理员可使用全部或指定租户范围；既有任务操作绑定记录所属租户，新建和父子记录遵守主平台目标租户规则。
- 查看、配置、添加、编辑、执行、确认、删除等动作分别校验业务权限，页面可见性不能替代服务端校验和 RLS。
- 删除检查失败、记录仍被引用或状态不允许时阻止办理，不自动清理已发生的设备运维历史。
